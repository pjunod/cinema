## Reader inventory — a zero exit is not a capability

The reachable macOS host has FFmpeg 9.0.1 from Homebrew. Both help probes
printed an unknown-capability error and exited zero:

```bash
ffmpeg -hide_banner -h demuxer=dvdvideo
# Unknown format 'dvdvideo'.
# Exiting with exit code 0

ffmpeg -hide_banner -h protocol=bluray
# Unknown protocol 'bluray'.
# Exiting with exit code 0
```

The implementation therefore classifies help from positive markers and the
diagnostic body, never from process status alone. This host cannot supply a DVD
or Blu-ray playback receipt.

The shipping Dockerfile installs `jellyfin-ffmpeg8`, but the runtime image was
not reachable from this session and the Docker daemon is unavailable locally.
Its DVD demuxer and Blu-ray protocol remain unverified. A version declaration
or package name is not a substitute for the two help probes plus decoded-frame
and seek cases.

## Input decision — one typed clause per opened source

The source builder follows the current upstream CLI contracts:

- DVD: `-f dvdvideo -title N -angle A -i PATH`, where public title and angle
  are explicitly nonzero.
- Blu-ray: `-playlist N -angle A -i bluray:PATH`, where a public opaque title
  resolves to the inspected playlist on the drive owner.
- Every input appends its own private options immediately before its own
  `-i`; a second audio or subtitle input cannot inherit optical selection.

The authoritative syntax is the
[FFmpeg DVD-Video demuxer](https://ffmpeg.org/ffmpeg-formats.html#dvdvideo)
and [Blu-ray protocol](https://ffmpeg.org/ffmpeg-protocols.html#bluray).
Neither upstream document proves that the packaged binary was compiled with
the required libraries.

## Hardware search — no drive was available to this task

Direct SSH to the documented `media1`, `lab3`, `lab4`, and `lab6` addresses
timed out. The reachable `billy` host reported only two NVMe disks and no
`/dev/sr*` block device. No eject, mount, media read, or drive-changing action
was attempted.

The following acceptance rows therefore remain open:

- actual drive model, firmware and host record;
- DVD and Blu-ray title enumeration;
- decoded first frame;
- forward, backward and chapter seek through the intended VOD path;
- copy and transcode across DVD cell and Blu-ray clip boundaries; and
- protection outcomes on representative physical media.

## M0 disposition — foundations may continue; M3 may not claim playback

The typed source identity, bounded inspector schema and argument construction
can proceed without hardware. Domain, Store, fake lifecycle, settings and
client presentation can also proceed against authored fixtures. Production VOD
integration remains dependent on a reachable packaged runtime and one
operator-identified DVD plus Blu-ray. No fixture result or compilation result
will close that row.
