## What this slice proves

The Apple and Android clients now decode the path-free optical wire contracts,
load authorized inserted drives into Home, navigate through disc and title
detail, expose resume, chapter, audio and subtitle choices, create an owner-routed
HLS session, report disc-specific progress, and release the session on exit.
Neither client receives a device or mount path. Optical playback remains an
explicit per-user grant supplied by the existing authenticated user model.

Commit `1b63b7e9` removes the interim native optical players. Both clients now
adapt the disc/title identity into their established player controller without
inventing file or item IDs. The shared controllers own session creation,
seeking, quality and track replacement, progress, teardown, Picture in Picture,
TV input, telemetry and terminal playback surfaces. Stable refusal codes reach
those surfaces as typed failures; neither client makes recovery decisions from
English server text.

Because one optical drive admits one physical reader, commit `d2ec5f56`
serializes viewer-directed audio, subtitle and quality replacement: each client
awaits acknowledged teardown of the exact incumbent before the shared
controller asks the server to reclaim the drive. This avoids a second-reader
race and an incorrect `optical_drive_busy` surface during an ordinary change.

Commit `67e5010bb` percent-encodes each opaque optical route component on
Apple. Commit `14d934251` makes Apple and Android serialize the selected
optical subtitle as `{index, burned: true}` in progress writes (and keeps the
audio index typed), matching the v2 durable rendition rather than having the
server reject a valid subtitle session as a different delivery.

Commit `201df0ef9` adds Apple and Android serialization regressions that pin the
same audio index and `{index, burned: true}` subtitle document. They are part of
the deferred final client lane and have not been run during construction.
