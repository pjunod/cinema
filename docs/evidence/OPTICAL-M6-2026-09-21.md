## What this slice proves

The Apple and Android clients now decode the path-free optical wire contracts,
load authorized inserted drives into Home, navigate through disc and title
detail, expose resume, chapter, audio and subtitle choices, create an owner-routed
HLS session, report disc-specific progress, and release the session on exit.
Neither client receives a device or mount path. Optical playback remains an
explicit per-user grant supplied by the existing authenticated user model.

Apple build 174 compiles for both supported simulator targets:

```bash
make apple-build
# plurx-iOS: BUILD SUCCEEDED
# plurx-tvOS: BUILD SUCCEEDED
```

Android build 112 compiles and packages the debug APK in the repository's
containerized toolchain:

```bash
make android

# BUILD SUCCESSFUL in 1m 46s
```

These are compile-only commands. Per the effort workflow, focused tests join
the single final fast-lane run after adversarial review rather than running
during construction.

## Still open

- Route optical sessions through the established Apple and Android playback
  controllers so fullscreen, TV input, Picture in Picture, watch-and-browse,
  quality replacement, telemetry and terminal surfaces remain single-owner.
- Map stable optical refusal codes through the native surface models without
  making recovery decisions from English text.
- Run physical TV remote/focus, track-change, seek, resume, phone/tablet and
  fullscreen/Picture in Picture acceptance on the final packaged candidate.

Compilation proves the native wire and navigation seams are sound. It does
not establish device behavior or complete M6.
