## What the commit establishes

- `PlaybackMediaFacts` separates codec, track, timeline, HDR, and bitrate facts
  from `MediaFile` identity and path. The existing file decision function is a
  compatibility adapter over the common decision engine.
- An optical title uses the same typed facts and is never offered as a direct
  range source. Even compatible codecs require owner-managed demux and
  segmented delivery.
- Optical durable session payloads are separately versioned, bounded, contain
  no path or file ID, and leave the strict legacy file-session envelope
  unchanged.
- Output identity includes insertion generation, disc, title, angle, selected
  tracks, locator, and plan digest. Reinsertion never reuses v1 output bytes.
- SQLite and Hiqlite have matching disc, title, progress, match, and explicit
  user-grant contracts. Missing `optical.play` defaults to false for a normal
  user and true for an administrator; an explicit override wins.
- User deletion cascades optical progress, item cleanup clears optional title
  matches, and inspection publication is transactional.

## Acceptance boundary

The focused contract covers same-label discs remaining distinct, transactional
rollback on an invalid title match, monotonic per-user progress, watched-state
stickiness, user cleanup, grant defaults/override, insertion-fenced output
identity, strict payload round-trip, common playback decisions, Hiqlite SQL
validation, and SQLite downgrade-fixture accounting.

An actual multi-node Hiqlite round trip remains part of the later cluster
acceptance. M1 does not unblock M3's physical VOD proof: the available local
FFmpeg still lacks both optical readers and no reachable drive has been
identified.
