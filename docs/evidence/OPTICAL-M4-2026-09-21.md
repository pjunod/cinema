**Status:** partial; owner relay built, playback placement remains open ·
**Branch:** `codex/optical-m0-foundations` · **Toolchain:** Rust 1.97.1

## What this slice proves

Media-pool protocol 7 adds an explicit `optical_v1` capability and a bounded
list of path-free drive snapshots. Each drive names its owner, public ID,
label, lifecycle state, insertion generation and disc identity. Device and
mount paths cannot enter the advertisement type.

The snapshot receiver requires the exact protocol, fresh expiry, the claimed
peer identity, unique bounded drive IDs, bounded lifecycle fields and
`optical_v1` whenever any drive is advertised. A stale peer snapshot expires
the drive ownership with the rest of that node's media capabilities.

Authenticated `GET /api/v1/optical/drives` now combines local drives with
fresh remote advertisements. Replicated disc metadata supplies the display
summary at any ingress. Commit `a59d1429` adds bounded, exact-request-authenticated
owner forwarding with signed responses for disc/title discovery, playback
decisions and generation-checked eject. The ingress accepts only currently
advertised owners from committed reachable membership; transport timeouts,
oversized or unsigned replies fail as stable `optical_owner_unavailable`.
Eject additionally requires voter authentication at the owner.

## Still open

- Authenticated start/progress forwarding to the drive owner.
- Optical recipe placement only on the owner and explicit no-adoption behavior.
- A live multi-node advertisement expiry and owner-loss observation.
- Source-aware VOD execution, which is the prerequisite for a real remote
  optical start.

The partial cluster surface is useful and safe on its own: discovery,
decision and eject reach the advertised owner, while no endpoint claims remote
playback started before the source-aware session controller exists.
