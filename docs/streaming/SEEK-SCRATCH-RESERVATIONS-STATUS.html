The limit this shipped with, now removed

Until 2026-09-24, transcoded output still reserved the whole per-session ceiling. FFmpeg's -f hls writes its own segment and playlist files, and there is no Rust hook before those writes; a measurement taken afterwards can only discover an overrun. Three candidate mechanisms were weighed — an owned output boundary (a substantial media-pipeline change), a hard writable quota (RLIMIT_FSIZE is per file; ffmpeg -fs counts cumulative muxed bytes and would truncate a long film; project quotas need privileged provisioning), and an enforced envelope (the timers are cadences, not proven maxima) — and none passed. The incident path and the more-than-three-producers case are both the copy path, so the repair reaches them; this is named rather than hidden, on the Developer tab too.

Resolved. -method PUT makes FFmpeg's HLS muxer upload each object instead of writing it, and crates/plurxd/src/scratch_put.rs receives the uploads, grants every piece against the ledger before it writes it, and renames each object into place only once everything it names is there. The muxer and its output are unchanged: real FFmpeg writes the same bytes both ways. The legacy copy writer, which had quietly been admitted on the small allowance with no boundary at all, uses the same endpoint.
