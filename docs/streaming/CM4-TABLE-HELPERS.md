# Table-driven CM4 transfer helpers

**Status:** built; exhaustive check passed, Cinema measurement pending deploy · **Owner:** Claude · **Updated:** 2026-11-27

They replace the correctly rounded split-float helpers of 2026-11-11
([status](DV_HDR_PROCESSING_STATUS.md)). Those needed a fused `fma` for
correct rounding: lavapipe does not fuse, so `run_pq_helper_exact.py`
accepted its unfused result there and `PLURX_DM_REQUIRE_FUSED_FMA=1`
demanded correct rounding on real GPUs. Now both fma modes are within the
contract; the variable only asks for the fused evaluation.

**2026-11-27.** The split-float helpers
above cost about 330 ms per 4K frame on Cinema's Intel iGPU (0x7d51), so a
display-targeted processed window (48 frames, 7.9 s budget) could not finish:
the same window renders in 0.66 s without a target and 17.8 s with one. The
helpers now read segment tables (`dm_pq_tables.h`, generated by
`controls/pq_table_gen.c` from the double-precision `controls/pq_reference.h`):
each float32 input picks one segment of its binade, and the segment's
polynomial (double-word value and slope, float32 tail) is evaluated without
any subnormal float operation. The contract changes from "correctly rounded
on every sample" to **at most 1 ULP from correctly rounded on every float32
input**, fused or unfused: `controls/pq_helper_exhaustive.py` checks all
2,139,095,040 non-negative finite inputs of each helper (inputs within the
reference's 2^-36 bound of a rounding midpoint are decided with 60-digit
Decimal). Fused, 99.97% of EOTF and 99.47% of OETF results are correctly
rounded and none is further than 1 ULP; unfused, 99.77% and 99.26%, also none
further. `run_pq_helper_exact.py` now requires the GPU to be bit-identical to
the header's CPU evaluation (FUSED, or UNFUSED with fma as a*b+c); the
no-`precise` mutation still fails. On an Apple GPU (MoltenVK) a 4K CM4 frame
takes 6.9 ms instead of 640 ms; all 80 parity cases pass, the 27 CM4 cases
with the same worst GPU-versus-double error (2.41e-4 PQ, dE_ITP 0.0042) and
the 53 others identical. Method identity `dolby-closed-form-cm4-cm29-v6`.
The licensed-reference audit and the Cinema measurement are pending deploy.

## Files

- `tools/dv_processing/dv_dm.h`: the helpers (`DV_DM_GLSL_CM4_PQ`) and the
  table texture (`dv_dm_pq_tex`, bound as `pqtab` on CM4 passes).
- `tools/dv_processing/dm_pq_tables.h`: generated tables; do not edit.
- `tools/dv_processing/controls/pq_table_gen.c`: the generator. Another
  libm can change the fitted low bits; a regenerated header must pass the
  exhaustive check again.
- `tools/dv_processing/controls/pq_reference.h`: the double reference.
- `tools/dv_processing/controls/pq_helper_exhaustive.py`: every input, fused
  and unfused, with and without flushed subnormals.
- `tools/dv_processing/controls/run_pq_helper_exact.py`: the GPU against the
  header's CPU evaluation (FUSED / UNFUSED / FAIL).
