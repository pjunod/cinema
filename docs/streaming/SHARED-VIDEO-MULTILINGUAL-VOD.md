# One video for two VOD soundtracks

**Status** · Built on `effort/shared-video-vod` (Claude Opus 5.5 owns). Lab-qualified for the AAC/AAC fixture on desktop Chrome: Proof A 20/20 in-place switches, Proof B one stored video. DTS→AAC, admission, fallback, restart, authorization and revocation are lab-qualified. Stale identity, eviction, failover, disk-full and crash-before-rename, and the canary (AC-5) are open. Project effort `E-70D9217053` owns progress and evidence.

A viewer starts an English-language movie, then selects French. Cinema keeps the same pictures moving while the sound changes. A second viewer can watch the same interval in English while both sessions read the same packaged video from one cache owner. Each viewer still receives the video over their own connection.

## First release

Start with a local indexed MKV, one copy-compatible H.264 SDR video stream, two identifiable stereo AAC-LC 48 kHz soundtracks, zero configured audio offset and one quality. Exercise the shipping web menu on one identified desktop hls.js/MSE browser build. This isolates the packaging change from audio encoder delay. Next qualify the motivating English AAC / French DTS case by converting only French to the same supported AAC output. Record separate results for each fixture. A client that can direct-play the file continues to do so.

The ordinary copy-VOD key includes the selected audio index, audio delivery recipe and offset. This is necessary for files that contain both video and audio. The web audio menu currently remembers the new selection, records a seek intent and requests a media change. Continuous quality already produces the opposite arrangement, one verified soundtrack alongside several video rungs. Its master assumes one audio track. Reuse its validation and track-clock machinery where applicable. Preserve existing muxed keys and readers. ### Implementation design (2026-11-21)

The split copy presentation is a sibling of the continuous-quality family and reuses its parts rather than adding a parallel stack.

* **Request.** The session request carries an optional `split_audio` capability that the hls.js/MSE web player sends. Admission grants it only when indexed copy is selected and every advertised soundtrack prepares. Otherwise the request uses the ordinary muxed copy route, with no error and no setting.
* **Video.** A copy `Recipe` gains an audio mode (`Muxed` or `Excluded`). An excluded recipe hashes a `video-only-v1` marker in place of the audio index, AAC flag, offset and audio delivery, so every language and viewer resolves one key. Its producer is the ordinary copy pipe with `-an`, cut on the same indexed grid.
* **Audio.** Each source soundtrack is the existing shared-AAC encoding (`VodSharedAudioRecipe`) for that stream on the source frame grid. It is prepared the same way `prepare_vod_soundtrack` prepares the continuous soundtrack, and attached as a private child reader of the session. The first release converts AAC sources too. This trades encoder CPU for one qualified audio producer, priming and lattice treatment, and avoids adding a new audio-copy segmenter.
* **Family and master.** `VodSplitCopyFamily` in `plurx-core` binds the verified copy video init and N verified soundtrack inits. Its master advertises one `#EXT-X-STREAM-INF` with `AUDIO="audio"` and one `#EXT-X-MEDIA` per soundtrack with `LANGUAGE`, `NAME` and the source stream index. `DEFAULT` names the requested track. Child playlists and objects use the existing `/{role}/{rendition}/…` routes and session authorization.
* **Player.** With an audio group present, `switchAudio` selects the matching `hls.audioTrack` on the same attachment. `AUDIO_TRACK_SWITCHED` commits the menu, preference and caption language. A failed alternate keeps the incumbent playing and reports the refusal. Other clients and native HLS keep the muxed route.

### Identity and timing contract

* **Video identity** includes an exact source revision, selected playable video stream, copy/bitstream transform, packet and cut-grid identity, timebase/origin, init/sample entry and byte-affecting producer version. Audit nested fingerprints for audio dependencies as well as video dependencies. Neither language selection nor viewer identity changes the underlying video key. A changed source with the same filename or a changed video transform must invalidate it.
* **Audio identity** includes source revision, selected source stream, copy or conversion settings, codec/layout/rate, gain/downmix, offset, trim/priming, producer version and the timeline/grid used by this package. Language is display metadata. Two tracks labelled French may be different streams. Verify the selected audible tracks after a source is replaced or reindexed.
* **Join by film time.** Audio samples have their own boundaries. Derive each audio interval from the common presentation timeline and actual packet/sample timestamps. Keep AAC frames intact and account for priming and trailing samples once. A second language must not move the video cuts or retime the video. Unknown source revision, unverified sync points or an incompatible output configuration select ordinary delivery at admission.
* **Ownership** stays per cache owner and source-access domain. Use one in-flight producer and one immutable committed object per video key/interval. Publish only verified complete objects under the current lease. Shared reads must survive individual session cancellation. Count temporary writes, retained objects and hard links in the storage audit. Keep legacy cache objects valid and let normal eviction retire them.

## Proof A — the picture keeps playing

1. Use numbered, moving, nonblack frames at a known cadence. Put recognizable English/French identifiers and a common timed sync signal in the two audio tracks. Capture displayed pixels and actual audio output independently of player telemetry. Calibrate capture cadence, dropped capture frames and A/V timing in the uninterrupted no-switch run. An ambiguous capture is inconclusive.
2. Drive **20 consecutive alternating switches** through the shipping menu while the movie plays, including taps near fragment boundaries and with buffered video ahead. Separately exercise rapid reversals, pause/resume, seeks with outstanding requests and an unavailable alternate. Capture tap, track request, first confirmed audible sample and displayed source frame on one time axis. Report per-switch delay and p50/p95/worst. Count a retained incumbent as a refusal.
3. For every healthy switch require the same media element, attachment generation, HLS session and video rendition, zero seek/reload/reopen, zero black or preparing frames, and no skipped or backward source pictures at the join. Allow ordinary display repetition at the calibrated source/display cadence. Reject an excess hold beyond one nominal display interval over baseline. Verify the intended audio signature arrives at the correct film time with no introduced silence/overlap above 20 ms, audible pop or accumulating sync drift. Apply the project's existing continuity criteria to each switch. [Continuity criteria and capture guidance](../playback-control/CONTINUOUS-QUALITY-BUILD.md#83-acceptance-is-a-per-switch-result-not-an-average)
4. Demonstrate that the observer catches an injected one-frame skip, a held picture, a forced reopen and a falsely reported audio switch. A clean callback trace cannot compensate for a failed output capture. Keep the original failed run and start a new series after a correction.

## Proof B — the packaged video is stored once

Measure the **same owner, exact source revision, video recipe and set of intervals**. The claim concerns packaged cache objects. Track source-file size, additional cluster replicas, temporary storage, manifests/audio and bytes delivered to each viewer separately.

1. Begin with an empty isolated cache. Have English request a fixed range of N video intervals. Inventory every produced object, including init, retained, temporary and muxed output. Record role, source identity, interval, video-sample digest, bytes written, successful producer/publication count, backing device/inode and allocated blocks. Hash demuxed video samples as well as whole files so the same pictures hidden inside two differently muxed containers are detectable.
2. While English still holds its session, have French request **exactly those N intervals**. Then repeat from a fresh cold cache with both requests released together. Replay warm, close one session, restart the daemon on the retained cache where supported, and repeat the inventory. Count unique backing objects across cache namespaces. Hard-linked names count once; independently produced files containing identical video fail even on a deduplicating filesystem. Use a controlled non-compressed, non-deduplicating filesystem or measured extent accounting for the physical-byte claim.
3. Pass when there is **one committed video init and N committed video-only fragments**, one successful video production per interval in the healthy cold run, and zero additional video production, video writes or allocated video blocks on the French/warm requests. Both playlists must resolve to those exact objects. Check each audio rendition separately. Report total cache delta and peak scratch. Audio, indices and manifests can grow. Compare the steady-state shape with one video payload plus English and French audio; derive savings from measured allocation against the ordinary baseline.
4. Validate the auditor by deliberately creating an independent copy of a video object and a muxed file containing the same pictures. Both must fail the proof. A hard-link alias must pass. Replacing the source or changing the video recipe must create a new generation. Exercise disk-full and crash-before-rename separately; retries may write temporary bytes, and recovery must converge to a single valid committed object without deleting an active viewer’s data.

## Rollout and rollback

Compare matched cold and warm runs for time to first visible frame, audio-switch latency, source reads, allocated video/audio bytes, peak scratch, CPU/GPU time, failures and session/producer cleanup. Establish startup and switch-latency budgets from the baseline and product targets before canary exposure. A bandwidth saving per viewer is not an acceptance criterion.

Start with the server able to read both formats and the web client able to consume either plan. Admit split playback only for the tested combination. Older builds, direct play, native Apple/Android, shared libraries, offline assets, Jellyfin, rolling, burns, HDR/DV and other rungs continue through their existing delivery paths. On admission failure use the ordinary muxed route. During playback a failed optional language change keeps the incumbent audible with an explicit result. If an actual media failure requires existing recovery, record the replacement separately from successful in-place switches.

Rollback stops new split admissions, drains existing sessions on their frozen manifests, and retains the split reader until their leases expire. Gate wider rollout on both proofs and matched performance evidence. Record implementation, lab acceptance and deployed qualification as distinct milestones in this ledger.
