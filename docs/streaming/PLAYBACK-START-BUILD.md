## 5. D2 — Server half of the start contract

**Root cause.** `create_with_purpose` (`crates/plurxd/src/http/hls/create.rs:2922-2981`) reads `x-plurx-startup-remaining-ms` and defaults to 10 000 ms; no client sends it, and `CreateStartupBudget::new` clamps to 10 s (`media_pool.rs:402`). The whole create runs under `timeout_at(budget.deadline)` (`:2952`) and, inside, the local worker is spawned detached (`spawn_create_worker`, `:4102`) and raced against `placement_deadline` (`:4158`); on expiry the handler answers a *codeless* 503 "local media worker exceeded the placement deadline" (`:4180`) and the late success drops its `StartedSessionGuard` (`:4164-4167`), which reaps the session the viewer never got. The remote arm (`start_remote`, `:4191`) has the same shape and a lost reply leaves the owner with a session nobody registers. Capacity refusals are strings prefixed `RETRYABLE_CAPACITY_PREFIX` (`transcode.rs:56`; `transcode/errors.rs:3-11`; 12 producers in `transcode/manager/start.rs`, `maintenance.rs`) and `session_start_error` maps them to a codeless 503 (`create.rs:5976`) — the one failure a retry would cure carries no code, while `startup_timeout` is retried by every client (`START_NOT_YET_CODES`, `playstart.rs`). `admit_live_with` polls to the full `QUEUE_WAIT` (5 s) even when a non-hardware decision is already final (`start.rs:346-350`, `match decision` at `:352-407`). The durable claim (`claim_media_session_request`, `create.rs:3372-3385`, expiry `now + 60 s`) already replays a *completed* activation to any ingress (`MediaSessionRequestClaim::Resolved`, `:3389-3434`); an `InFlight` claim (`plurx-core/src/domain.rs:1192-1200`) has no cross-ingress join.

**Build.**
1. **Clients send the budget.** Web: `openSession` (`crates/plurxd/src/web/player/directed-change.js:890`) sets `x-plurx-startup-remaining-ms` from the preparation clock started in `beginPlaybackPreparation` (`player/measurements.js:71`), also on each retry of `openSessionRetryingNotYet` (`:1060-1170`). Apple: the create request in `clients/apple/Sources/PlayerControllerSupport.swift` (search `hls/sessions`) from the 20 s decision deadline (`:124-126`) / 60 s watchdog. Android: `SharedDecisionClient.kt:159` from `PlaybackTelemetry.kt:479`'s 30 s startup deadline. Bump Apple (`make apple-build-bump`) and Android `versionCode`; `tests/validation/test_mobile_versions.py` enforces it.
2. **Capacity class split.** Enumerate every `capacity_error(` producer (`rg "capacity_error\(" crates/plurxd/src/transcode`); classify each as *waitable* (slot/CPU/queue — a retry can succeed) or *terminal* (smaller height required, scratch ceiling, replacement deadline). Replace the string prefix with `enum CapacityRefusal { Waitable { retry_after_ms }, Terminal(&'static str code) }` surfaced through `SessionStartError`; `session_start_error` maps `Waitable` → 503 `transcode_capacity_pending` with `Retry-After` (seconds, from the admission estimate; the code is already in `START_NOT_YET_CODES`), `Terminal` → its own code (`transcode_height_unavailable`, `transcode_scratch_exhausted`, `replacement_expired`). Add the codes to `tests/playback/playback-surface-contract.json` (rows `create_503_not_yet` / terminal) and to the three clients' lists (`web/playback-policy.js:960-1000`, `PlayerControllerSupport.swift:2670-2677`, `PlaybackPolicy.kt:200-220`); `tests/validation/test_control_wire_conformance.py` is the gate.
3. **One owner from dispatch to activation.** The durable claim row is the request identity. (a) Both placement-timeout arms answer 503 `startup_timeout` with `Retry-After` and **do not drop the guard**: the detached worker keeps its `StartedSessionGuard` and, on success, publishes activation under the claim (`publish_media_session_activation`) exactly as the synchronous path does (`:4791-4838`), so the claim becomes `Resolved`; on failure it releases the claim with the error. (c) The remote arm: `start_remote` success registers activation on the *owner* under the same claim so a lost reply is recovered by (b). Document the 10 s server clamp vs the client's remaining time in `docs/API.md` under the create route.
4. **Admission returns when final.** In `admit_live_with`, return as soon as `decision` is `Software`, `Refused`, or `WaitingForBackground` with a Live priority that will take over (`:487`), instead of sleeping to the deadline; keep the poll only while the decision can still improve to hardware.
