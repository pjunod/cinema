## 1. Target contract (what PLAYBACK-START.md will say when the effort closes)

- A start is one client clock. The client sends `x-plurx-startup-remaining-ms`; the server answers within it with exactly one of **ready** (playlist URL) or **not yet** (typed code, `Retry-After`, the server's own estimate). No ladders, no codeless refusals. The server's own 10 s clamp is documented as distinct from the client's remaining time.
- Create is one snapshot read → one pure decision → at most two durable writes (admission claim; activation publication — the desired selection folds into the claim) → spawn → answer. Nothing advisory or speculative runs before the answer. Create p99 < 1 s on the fleet.
- Every engine publishes its first playlist at **3 complete segments or ENDLIST**, with `EXT-X-TARGETDURATION` fixed before first publication; `ENDLIST` is appended to the same EVENT URI and an immutable VOD playlist is exposed separately for later attaches (RFC 8216 §6.2.1).
- The fragment index is a by-product of the first play of a title, is sparse-by-range until complete, and survives a deploy. The background queue indexes titles nobody has played and fills the gaps.
- Settings, routes and catalogue are node-local views of the applied raft log; only fences are consistent reads.
- Every start is attributable in Activity → Starts by attempt id: route, the refusal that chose it, phase timings, owner node, the title's index state.
