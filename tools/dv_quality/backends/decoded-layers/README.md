# Encoded dual-layer decode probe

This source-only experiment builds a pinned FFmpeg 9 decoder/splitter, muxes six legal 64 × 64 Main10 BL and EL pictures with generated P7 FEL RPUs, and verifies actual display-frame association before invoking the renderer. It proves bounded synthetic bitstream mechanics. It does not certify P7 container/profile conformance, film fidelity, creative trims, output target mapping, hardware performance, queue/backpressure behavior or production fallback.

## Replay

```sh
sh replay.sh /absolute/new-scratch /absolute/approved-parsed-renderer-replay /absolute/reviewed-parsed-bundle
```

The prerequisite supplies the already-built libplacebo API 374 prefix, libdovi C API header/static library and validated `image-id.txt`. The prerequisite lock binds every copied library/header/pkg-config file and the relative `.so` link to the exact reviewed artifact set. It additionally requires the reviewed receipt/source-lock hashes, source revisions, original libdovi source archive and resolved Cargo lock. Validation runs before and after copying. Altered dependency builds require a new reviewed lock; dynamic image identity alone does not establish source/library provenance. The script accepts the supplied local Linux ARM64 image digest rather than a machine-specific hardcoded image. All writes go to a new scratch directory. Source fetching carries neither Git history nor credentials; no host/fleet packages are installed. FFmpeg source is pinned to `bf1b838f2ab88b4f8fd83443325c782ea0e0f7fa`, archive SHA256 `fb1931fd4eb29297ee1c1017a24f800c4d8fbea35b4f2aaeb28308a48a9149b4`. No upstream source patches are applied. The configured decoder/parser, dovi_split/HEVC filters, Matroska/HEVC demux, Matroska mux and file protocol are built statically; ASM, networking, automatic dependencies and unused programs/libraries are disabled. This selected FFmpeg build uses its default LGPL license. Existing FFmpeg 5.1.9/x265 3.5 in the prerequisite image encode the fixtures as separate processes; x265 licensing remains distinct from the decoder build. The image's apt/pip recipe still uses live resolution and can drift on rebuild, as documented by the prerequisite.

Generated six-RPU fixtures, their own-parser JSON, exact Rust source and pinned libdovi/Rust 1.97.1 generation receipt are retained. Their identity reshape and LINEAR_DZ NLQ are deliberately simple. Each fresh RPU has a distinct L1 max/average tag. This does not exercise legitimate `use_prev_vdr_rpu_flag` or other reuse semantics.

## Encoded timing and pairing

The encoder creates real timestamped Matroska BL/EL inputs at a requested 24 fps. The muxer preserves their actual PTS/DTS/duration; it never assigns timestamps from frame indices. Matroska's actual time base is 1/1000. Display PTS are 0, 42, 83, 125, 167 and 208 ms; packet/frame duration is 41 ms, while adjacent PTS gaps alternate 41/42 ms. Initial reordered DTS can be unknown and are recorded as null. The actual encoded streams are checked as Main10/yuv420p10le 64 × 64 by ffprobe, independently of requested encoder options.

The wrapper uses four-byte length-prefixed base NALs, each original EL NAL inside an UNSPEC63 two-byte outer header, and a complete generated UNSPEC62 RPU suffix. The muxer records declared synthetic DV configuration and EL HEVC configuration in Matroska. Proper codec decoding and configuration round trip do not establish certified Dolby container conformance.

No-reorder coded PTS arrive in display order. B-frame coded PTS arrive 0, 125, 83, 42, 208 and 167 ms; both independent HEVC decoders emit 0, 42, 83, 125, 167 and 208 ms. The checker verifies original-container timing survives demux and split, pairs decoded layers by exact rational PTS, checks actual durations, and requires byte-exact BL/EL native pixels and decoder-attached raw RPUs against the known source fixture. Each receipt binds the original and compound containers, trace, source definition, native pictures and RPU hashes. Logical source indices are labels used to select known RPU tags and native-code references; they are not replacement decoder timestamps.

## Negatives and stale metadata

Missing and swapped EL payloads cause actual HEVC reference-chain failures: the helper exits cleanly with status 1 with a recorded missing-reference and controlled decoder-send diagnostic. Association is incomplete in these cases. Each negative must match its exact expected stage/reason; missing-reference diagnostics must match the entire known message sequence and POC, ignoring only volatile HEVC pointer addresses. Crashes, other exit statuses, extra diagnostics and unrelated association failures fail the test suite. This is not the future product adapter's explicit queue/association refusal or fallback implementation.

Swapped and missing RPU payloads decode successfully, but the fixture checker refuses acceptance. Swapped RPUs violate the known source tag/RPU association. This is a test of a deliberately wrong fixture association; it does not imply a general adapter can detect creatively incorrect metadata that an otherwise valid source intentionally provides.

In the reordered missing-RPU fixture at 83/1000, BL raw RPU is absent while BL DOVI_METADATA remains present with L1 max 4092/average 2045, inherited from the earlier coded 125 ms packet instead of the expected 83 ms tag 4093/2046. EL has neither RPU nor metadata side data because the EL extraction mode intentionally omits RPU. Layer distinction, coded/display order, PTS and hashes are preserved. Side-data presence alone is therefore insufficient evidence of fresh per-frame RPU acceptance. Legitimate encoded reuse remains a separate, untested state-machine requirement.

## Renderer evidence

Only fully accepted normal associations reach the copied public API 374 renderer. It reparses each actual decoder-attached RPU and samples actual decoded native YUV420P10 BL/EL planes, with explicit 10-bit representation and point chroma reconstruction. Its shader-side namespace fix and bounded identity/fractional-NLQ metadata projection come from the approved probe. Other curves/depths/ranges, bounded residual clipping and creative trims remain unsupported.

Twelve decoded display pictures run positive/zero/omitted/shifted/disabled EL controls, both before mapping and through the 10,000 / 0.005 nits BT2020 clip renderer. All 120 comparisons pass scalar matrix/PQ arithmetic controls, observed maximum 1.056e-5 PQ and one RGB48 code. The 2e-5 PQ/2-code bounds were inherited from the prior probe and written before the first numerical comparison of these decoded outputs, after output generation; they are not a formal preregistered media-quality bound. The scalar reference follows the public shader algebra and fixture coefficients and is not an independent Dolby oracle. Zero/omitted/disabled controls must have no residual; shifted integer output is checked against its own expected arithmetic. The checker revalidates current decoded BL/EL/RPU bytes and requires each renderer association receipt to match the current accepted pair. All five actual renderer events must report the exact accepted PTS/duration and control flags. Every comparison binds the native BL/EL/RPU, association, probe and accepted container/trace context hashes. GPU receipt PTS/duration come from the validated actual association.

The controlled resource graph is six timestamped packets per layer, independent single-thread HEVC contexts, exact-PTS pairing of at most six decoded pictures, fresh-RPU parser ownership, decoded texture upload, reconstruction shader, full renderer, readback and artifact checker. Containers have 2 CPUs / 2 GiB caps; this is a fixture bound rather than a measured physical performance or full queue contract. The final HDR10 encoder endpoint is already proven separately in the approved parsed-RPU probe and is not requalified by this decode task.
